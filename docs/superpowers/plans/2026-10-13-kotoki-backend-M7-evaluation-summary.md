# Kotoki Backend — M7 Evaluation & Summary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setiap event `session.completed` menghasilkan evaluasi pasca-sesi (`evaluations` + `evaluation_findings`, event `evaluation.completed`/`evaluation.failed`) dan `sessions.summary_text`, dibaca lewat `GET /api/v1/sessions/{id}/evaluation`, dengan tooling kalibrasi golden set yang berjalan pada dataset contoh.
**Architecture:** Paket fitur `evaluation` (→ `content`, `prompt`, `provider`, `events`) dan `summary` (→ `prompt`, `provider`, `events`) memegang aturan, port `Store`/`Tx`/`Source`, dan `Consumer` yang memenuhi `amqp.Handler` secara struktural (hanya mengimpor `events`); `postgres`, `objectstore`, dan `httpapi` hanya mengimplementasikan port/handler. Prompt, rubric, `output_schema`, dan `llm_params` hidup di `prompt_versions` (seed `0070_prompts.sql`); kode hanya merender, memvalidasi, dan memfilter. Pronunciation memakai `AsyncRouter.AssessPronunciation` dan tidak pernah menggagalkan evaluasi. Kalibrasi = paket murni `evaluation/golden` + subcommand `kotoki-cli eval-golden`.
**Tech Stack:** Go 1.25, chi, pgx + sqlc, errgroup (`x/sync`), `santhosh-tekuri/jsonschema/v6`, `golang.org/x/text/unicode/norm` (NFKC; dipakai juga M2), aws-sdk-go-v2 S3 (objectstore), prometheus client, testify, testcontainers (postgres, rabbitmq, minio).
**Spec:** docs/superpowers/specs/2026-10-12-kotoki-backend-design.md — Bab 10 (§10.1–§10.14), §9.9.6 (summary), §9.5.2–9.5.3 (payload yang diterbitkan), §9.7 (kontrak handler), §8.2.5/8.2.7/8.2.8 (port provider yang dipakai), §8.9.5 (fake), §6.8.1/§6.10.1 (render & fixture), §5.9.6 + §5.10 (endpoint & kode error).
**Master plan:** docs/superpowers/plans/2026-10-13-kotoki-backend-00-master.md (Global Constraints di sana berlaku untuk semua task)
**Depends on:** M6 (M6 plan: `amqp.Handler/NewConsumer/Dial/NewConfirmPublisher/OutboxPublisher`, `events.Envelope/Delivery/DecodePayload[T]/Permanent/PermanentError/ErrAlreadyProcessed/ProcessedEvents/QueueEvaluation/QueueSummary/SessionCompletedV1/EvaluationCompletedV1/EvaluationFailedV1/ProducerWorker`, builder `events.NewEvaluationCompleted(id, now, producer, userID, EvaluationCompletedV1)` dan `NewEvaluationFailed(...)`, `(*postgres.Tx).Processed()`, `objectstore.Client` (`GetObject/DeleteObjects/ListObjects/ErrNotFound`), `testutil.NewRabbitMQ/RabbitAdmin/NewMinIO`, `cmd/worker` `buildConsumers`/`consumerDeps` dengan case `evaluation`/`summary` = `errHandlerNotImplemented`), M4 (`provider.AsyncRouter/EvaluationRoute/EvaluationProvider/StructuredRequest/TextRequest/PronunciationRequest`, `prompt.Render/Template/Params/RegisterFixtures`, `fake.NewEvaluation/NewPronunciation`), M3 (`content.PromptVersion/Repository/EffectiveFormality`, `session.QueryService`, `events.OutboxWriter`, `seed/0070_prompts.sql` berisi CONVERSATION+OPENING, `TestRouteTable`, helper `httpapi`), M1 (migration `000019_evaluations` + `000020_messaging`, `testutil.NewPostgres/SeedUser/SeedContent/SeedSession`).

## Global Constraints

- Master Global Constraints berlaku.
- Skor dimensi integer 0–100 absolut; `overall_score = round(mean(non-null), 2)`; semua null → NULL; status `PENDING|RUNNING|COMPLETED|FAILED`; finding type 18 nilai (16 dari LLM + `MISPRONOUNCED_WORD`, `PROSODY_ISSUE` dari kode); severity `INFO|MINOR|MAJOR` (§10.1).
- Insufficient evidence bila `user_turn_count < 3` ATAU `user_speech_seconds < 20` ATAU `active_seconds < 60` (env `EVAL_MIN_USER_TURNS/EVAL_MIN_USER_SPEECH_SECONDS/EVAL_MIN_ACTIVE_SECONDS`) → `COMPLETED`, semua skor NULL, `pronunciation_status=SKIPPED`, tanpa findings/LLM/pronunciation, `summary_feedback` = teks tetap §10.4; user turn eligible = status `COMPLETED|INTERRUPTED|FAILED`, `user_text` ≥ 2 rune setelah trim.
- Consumer: queue `evaluation.session_completed`, `SupportedEvents={"session.completed":1}`, timeout 200 s (`EVAL_HANDLER_TIMEOUT`); summary: `summary.session_completed`, timeout 60 s; retry 5s/30s/2m/10m, total 5 percobaan (D-092).
- Maksimum 3 panggilan `GenerateJSON` per delivery (primary → repair di primary → fallback); `llm_params` seed v1 `{"temperature":0,"max_output_tokens":4000,"seed":42}` (nilai DB menang; default kode hanya bila key tidak ada); `SchemaName = kotoki_evaluation_rubric_v1`; `RequestID = "EVALUATION:<session_id>"`; repair menyertakan output lama dipotong 8.000 karakter.
- Filter finding: `confidence < 0.6` dibuang; maks 15 non-STRENGTH + 3 STRENGTH; `original` harus substring ternormalisasi (NFKC, tanpa whitespace dan `、。，．！？!?「」…・`) dari `user_text`; >50 % finding ditolak aturan = output invalid (repair).
- Pronunciation: kandidat turn eligible ber-audio, ≥ 4 rune, durasi 1–30 s; urut durasi menurun; maks 10 utterance / 120 s; < 3 kandidat atau < 10 s → `INSUFFICIENT_AUDIO`; sukses < 50 % atau < 3 → `PROVIDER_ERROR`; konkurensi 3; deadline panggilan 35 s; skor = rata-rata berbobot `AudioMs`; `confidence["PRONUNCIATION"]=0.90`; findings `MISPRONOUNCED_WORD` (accuracy < 60; maks 5 kata unik; MAJOR < 40) dan `PROSODY_ISSUE` (prosody < 60; maks 2; MINOR) dengan confidence 0.80; tanpa `audio_consent` → `NO_CONSENT` (audio tidak diunduh).
- `FAILED` final tidak menulis `processed_events` dan tidak menghapus audio; `COMPLETED` menghapus `user_audio_object_key` (di transaksi) lalu objek `audio/tmp/{session_id}/` (setelah commit, best-effort).
- `GET /api/v1/sessions/{id}/evaluation`: non-terminal → `409 SESSION_NOT_ENDED` (`details.session_status`); terminal tanpa `started_at` → `404 EVALUATION_NOT_AVAILABLE`; selain itu `200` (`PENDING` disintesis bila belum ada baris) dengan `Retry-After: 3` untuk `PENDING|RUNNING`; user lain/tidak ada → `404 SESSION_NOT_FOUND`; `failure_message = "Evaluasi untuk sesi ini gagal diproses. Tim kami sudah diberi tahu."`.
- Summary: Jepang, ≤ `SUMMARY_MAX_CHARS`=300 karakter, `Profile STANDARD`, `Task "SUMMARY"`, default `max_output_tokens` 400 / `temperature` 0.3 hanya bila key tidak ada; tidak dibuat bila `payload.user_turn_count == 0`; transcript > 30.000 karakter → baris AI dipotong 150; `UPDATE … WHERE summary_text IS NULL`; tidak menaikkan `sessions.version`.
- Event tidak dikirim untuk user `DELETED` (hanya `MarkProcessed` lalu ACK); tidak ada teks user/AI/prompt di log, span, atau label metrik.

## Review Focus

(Tidak ada butir master #1–5 yang dimiliki M7; berikut kondisi tersirat spec, masing-masing diuji di task pemilik.)
1. **Event ganda / dua pod memproses salinan sama:** tepat satu evaluasi COMPLETED dan satu `evaluation.completed` — Task 13 (unit `MarkProcessed`/`status<>'COMPLETED'`), Task 15 (paralel nyata di PG).
2. **Sesi terlalu singkat (2 turn, ucapan 19 s, 59 s):** tidak boleh memanggil LLM/pronunciation, tetap `COMPLETED` + event terbit — Task 2 (batas), Task 13, Task 15.
3. **Evaluator berhalusinasi atau menghukum artefak STT:** finding yang `original`-nya bukan substring, confidence < 0.6, atau tipe/dimensi salah dibuang; >50 % ditolak → repair → fallback → `INVALID_MODEL_OUTPUT` — Task 7, 8, 9, 15.
4. **Privasi audio:** capture/penilaian hanya dengan consent saat evaluasi, audio terhapus setelah COMPLETED tetapi bertahan setelah FAILED, user `DELETED` dilewati tanpa panggilan provider — Task 10, 13, 15.
5. **Isolasi & matriks API:** sesi user lain = 404 tanpa bocor; `FAILED` yang pernah ACTIVE tetap dievaluasi; tiga keadaan 409/404/200 — Task 16, 19.
