Catatan pembulatan terhadap tabel spec: egress STT 340,5 Mbps (spec "±341"), PG tx 142/s (spec "±145"), TTS 133 stream (spec "±135"), LLM 167 stream (spec "±170"), Redis 3.680 ops/s (spec "±3.700"); semuanya dalam toleransi tes (`TestDerive_At1000CCU`). Budget koneksi PG 187 (pada 1.000 CCU) dan 263 (semua Deployment di HPA max) cocok dengan tabel §13.3.2.

## Perintah validasi terhadap ukuran nyata (MANUAL GATE Task 24, MG-2)

1. Jalankan G4a di staging sesuai plan MG-2 (`--gate g4a`, 10 pod realtime, `REALTIME_READY_MAX_SESSIONS=101`).
2. Dari Prometheus staging, isi berkas JSON hasil ukur (semua kunci wajib; kunci hilang ditolak, bukan dianggap 0):

```json
{"cpu_cores_per_100_sessions": <rata-rata core realtime / (sesi/100)>,
 "mem_mb_per_100_sessions": <working set MB realtime / (sesi/100)>,
 "stt_egress_mbps": <laju byte keluar ke vendor STT>,
 "pg_tx_per_sec": <xact_commit+xact_rollback per detik>,
 "redis_ops_per_sec": <instantaneous_ops_per_sec>}
```

3. `make capacity ARGS="--ccu 1000 --measured measured.json"`: exit 0 bila semua `OK`, exit 1 bila ada `FAIL`. Batas: CPU <= 1,5 core/100 sesi, memori <= 390 MB/100 sesi (1,3 x 300), lainnya <= 1,3 x model (di bawah model juga lulus).
4. Bila gagal: ubah `REALTIME_MAX_SESSIONS`/resource, perbarui register D-103 dan §13.10.2 lebih dulu (plan MG-2).

Status butir kapasitas: ukuran pod/HPA nyata, K10-K12, dan 100 sesi/pod **belum dibuktikan** (MANUAL GATE).
